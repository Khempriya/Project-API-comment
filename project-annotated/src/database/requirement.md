# ระบบข้อมูลฟิตเนส

## ชื่อระบบ

ระบบข้อมูลฟิตเนส

## วัตถุประสงค์

ระบบจัดการข้อมูลเครือข่ายสาขาฟิตเนส เพื่อช่วยแก้ปัญหาการเก็บข้อมูลที่กระจัดกระจาย
**กลุ่มผู้ใช้เป้าหมาย:** พนักงานฟิตเนสประจำสาขา และ ผู้ดูแลระบบ

## รายการ Use Case หลัก

1. พนักงานสามารถลงทะเบียนสมาชิกใหม่ได้
2. พนักงานสามารถบันทึกการสมัครแพ็กเกจของสมาชิกได้
3. ผู้ใช้ทั่วไปสามารถดูข้อมูลสาขาฟิตเนสและราคาได้
4. ผู้ดูแลระบบสามารถเพิ่ม แก้ไข หรือลบข้อมูลสาขาฟิตเนสได้
5. ผู้ดูแลระบบสามารถดึงรายงานประวัติการสมัครแพ็กเกจของสมาชิกทั้งหมดได้
6. พนักงานสามารถแก้ไขหรือลบข้อมูลสมาชิกได้ (เพิ่มในระยะที่ 3)
7. พนักงานสามารถแก้ไขหรือลบการสมัครแพ็กเกจได้ (เพิ่มในระยะที่ 3)

### รายละเอียด Use Case

#### Use Case: 1. ลงทะเบียนสมาชิกใหม่

Actor: พนักงาน
Precondition: ลูกค้าต้องการสมัครสมาชิกและแจ้งข้อมูลส่วนตัว

Main Flow:

1. พนักงานกรอก ชื่อ นามสกุล และอีเมล ของลูกค้า
2. ระบบตรวจสอบว่าอีเมลที่ระบุมีการใช้งานในระบบแล้วหรือไม่
3. ระบบบันทึกข้อมูลสมาชิกลงตาราง members
4. ระบบแสดงข้อความแจ้งเตือน "ลงทะเบียนสมาชิกสำเร็จ"

Alternative Flow:
ไม่มี

Exception Flow:
2a. อีเมลที่ระบุมีอยู่ในระบบแล้ว -> ระบบแสดงข้อความแจ้งข้อผิดพลาด "อีเมลนี้มีอยู่ในระบบแล้ว" และไม่บันทึกข้อมูล

Postcondition: บัญชีสมาชิกใหม่ถูกสร้างขึ้นในระบบ

#### Use Case: 2. บันทึกการสมัครแพ็กเกจ (Subscription)

Actor: พนักงาน
Precondition: ลูกค้ามีข้อมูลลงทะเบียนเป็นสมาชิกในระบบเรียบร้อยแล้ว

Main Flow:

1. พนักงานเลือกชื่อสมาชิก และเลือกสาขาฟิตเนสที่ลูกค้าต้องการสมัคร
2. ระบบตรวจสอบว่าสมาชิกคนนี้เคยสมัครสาขานี้ไปแล้วหรือไม่
3. ระบบบันทึกข้อมูลการสมัครลงตาราง subscriptions
4. ระบบกำหนดสถานะแพ็กเกจเป็น "active"

Alternative Flow:
ไม่มี

Exception Flow:
2a. ลูกค้าเคยสมัครสาขานี้ไปแล้ว -> ระบบแสดงข้อความแจ้งข้อผิดพลาด และไม่บันทึกการสมัคร

Postcondition: ออเดอร์มีสถานะ "active" หรือยังคงสถานะเดิมพร้อมข้อความ error

#### Use Case: 3. ดูข้อมูลสาขาฟิตเนสและราคา

Actor: ผู้ใช้ทั่วไป
Precondition: ผู้ใช้เข้าสู่หน้าระบบ

Main Flow

1. ผู้ใช้เลือกเมนูค้นหาสาขา
2. ระบบดึงข้อมูลจากตาราง gyms
3. ระบบแสดงรายการสาขาทั้งหมด พร้อมที่อยู่ และราคาค่าบริการรายเดือน

Alternative Flow:
ไม่มี

Exception Flow:
2a. ระบบไม่พบข้อมูลสาขาในฐานข้อมูลเลย -> ระบบแสดงข้อความแจ้งเตือน "ยังไม่มีข้อมูลสาขาฟิตเนส"

Postcondition: ผู้ใช้ได้รับข้อมูลรายการสาขาฟิตเนสที่ต้องการ

#### Use Case: 4. จัดการข้อมูลสาขาฟิตเนส

Actor: ผู้ดูแลระบบ
Precondition: เข้าสู่ระบบด้วยสิทธิ์ผู้ดูแล

Main Flow:

1. ผู้ดูแลระบบระบุข้อมูลสาขาใหม่
2. ระบบตรวจสอบความครบถ้วนของข้อมูล
3. ระบบบันทึกข้อมูลสาขาใหม่ลงตาราง gyms
4. ระบบแสดงข้อความอัปเดตข้อมูลสำเร็จ

Alternative Flow:
1a. ผู้ดูแลระบบเลือก "ลบ" ข้อมูลสาขา -> ระบบลบสาขา และลบประวัติการสมัครทั้งหมดที่ผูกกับสาขานั้นออก

Exception Flow:
2a. ผู้ดูแลระบบระบุข้อมูลไม่ครบถ้วน -> ระบบแสดงข้อความแจ้งข้อผิดพลาด และไม่บันทึกข้อมูล

Postcondition: ข้อมูลสาขาฟิตเนสในระบบได้รับการอัปเดต

#### Use Case: 5. ตรวจสอบประวัติการสมัครแพ็กเกจ

Actor: ผู้ดูแลระบบ
Precondition: มีข้อมูลการสมัครบันทึกอยู่ในระบบ

Main Flow:

1. ผู้ดูแลระบบเลือกเมนูตรวจสอบประวัติ
2. ระบบดึงข้อมูลจากตาราง subscriptions เชื่อมโยงกับ members และ gyms
3. ระบบแสดงรายการประวัติการสมัครทั้งหมด

Alternative Flow:
1a. ผู้ดูแลระบบค้นหาด้วยชื่อสมาชิก -> ระบบแสดงผลเฉพาะประวัติการสมัครของลูกค้ารายนั้น

Exception Flow:
2a. ระบบไม่พบประวัติการสมัครใดๆ เลย -> ระบบแสดงข้อความ "ไม่พบประวัติการสมัครในขณะนี้"

Postcondition: ผู้ดูแลระบบได้รับข้อมูลรายงานประวัติการสมัคร

#### Use Case: 6. แก้ไขหรือลบข้อมูลสมาชิก

Actor: พนักงาน
Precondition: สมาชิกที่ต้องการแก้ไขหรือลบมีอยู่ในระบบ

Main Flow:

1. พนักงานเลือก "แก้ไข" ที่รายชื่อสมาชิก แล้วแก้ชื่อหรืออีเมล
2. ระบบตรวจสอบความถูกต้องของข้อมูลและตรวจว่าอีเมลไม่ซ้ำกับสมาชิกคนอื่น
3. ระบบอัปเดตข้อมูลในตาราง members
4. ระบบแสดงข้อความ "อัปเดตข้อมูลสมาชิกสำเร็จ"

Alternative Flow:
1a. พนักงานเลือก "ลบ" และยืนยัน -> ระบบลบสมาชิก และลบประวัติการสมัครทั้งหมดของสมาชิกนั้นออก (ON DELETE CASCADE)

Exception Flow:
2a. อีเมลซ้ำกับสมาชิกคนอื่น -> ระบบแสดง "อีเมลนี้มีอยู่ในระบบแล้ว" และไม่บันทึก
2b. ไม่พบสมาชิกที่ระบุ -> ระบบแสดง "ไม่พบสมาชิกที่ระบุ"

Postcondition: ข้อมูลสมาชิกในระบบถูกแก้ไขหรือถูกลบ

#### Use Case: 7. แก้ไขหรือลบการสมัครแพ็กเกจ

Actor: พนักงาน
Precondition: การสมัครที่ต้องการแก้ไขหรือลบมีอยู่ในระบบ

Main Flow:

1. พนักงานเลือก "แก้ไข" ที่ประวัติการสมัคร แล้วเปลี่ยนสาขา วันที่เริ่ม หรือสถานะ (active / expired / cancelled) สมาชิกของการสมัครเปลี่ยนไม่ได้
2. ระบบตรวจสอบข้อมูล และตรวจว่าสาขาใหม่มีอยู่จริง
3. ระบบอัปเดตข้อมูลในตาราง subscriptions
4. ระบบแสดงข้อความ "อัปเดตการสมัครแพ็กเกจสำเร็จ"

Alternative Flow:
1a. พนักงานเลือก "ลบ" และยืนยัน -> ระบบลบการสมัครนั้นออก

Exception Flow:
2a. สมาชิกคนเดิมเคยสมัครสาขาที่เลือกแล้ว -> ระบบแสดง "สมาชิกคนนี้เคยสมัครสาขานี้ไปแล้ว" และไม่บันทึก
2b. ไม่พบสาขาหรือการสมัครที่ระบุ -> ระบบแสดงข้อความไม่พบข้อมูล

Postcondition: ข้อมูลการสมัครแพ็กเกจในระบบถูกแก้ไขหรือถูกลบ

## รายการ Resource หลักของระบบ

1. **gyms**
2. **members**
3. **subscriptions**

### ความสัมพันธ์ระหว่าง Resource

- `gyms` กับ `subscriptions` (1:N)
- `members` กับ `subscriptions` (1:N)
